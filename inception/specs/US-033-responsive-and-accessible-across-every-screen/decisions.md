# US-033 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                                                                                                     | Rationale                                                                                                                                                                                                                                                                                    | Alternatives rejected                                                                                                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | Verify the width/layout ACs (AC-01–04) by driving the real dev server in the browser pane and writing CSS-source-proxy tests, not by introducing Playwright. | No e2e layer exists yet in this repo (`ADR-006-e2e-testing-layer.md` is referenced by the framework but was never written here); adding Playwright is itself a Complex-tier new-dependency decision, disproportionate to a verify-only story. `apps/ui/src/styles/index.css:14-18` already documents that jsdom has no layout engine, and `Dialog.spec.tsx:146-150` already established the "stylesheet is the honest proxy, human verifies by eye" pattern this plan reuses. Confirmed with the human before planning (2026-09-21). | Introduce Playwright + ADR-006 now and automate the sweep. Rejected: out of scope for a story that "verifies; does not build," and the human declined it when asked directly. |
| D-02 | Prove AC-05/AC-07 mostly by adding `(US-033/AC-##)` citations to already-passing tests, rather than writing new ones.                                          | The behaviour these ACs require was already built and tested by the 32 stories this one depends on (e.g. `StatusChip.spec.tsx`, `Dialog.spec.tsx`, `AccountRowMenu.spec.tsx`). Writing a second, parallel test would duplicate proof and could drift from the original. Precedent: `3a32a42` "trace suggest-a-password to its own story [US-022]" did the same for US-021→US-022.                                                                                                                                              | Write fresh, story-named test files for every AC. Rejected: duplicates existing coverage and is what the US-022 precedent explicitly avoided.                                                            |
| D-03 | Do not write a passing AC-07 test claiming the desk radio-group's arrow-key model works.                                                                       | `SCR-003-book-a-desk.md:168` promises "one tab stop, arrows move selection" for the desk list; no code implements it (`DeskRow.tsx`, `ZoneGroup.tsx`, `BookADesk.tsx` have no `onKeyDown`/roving-tabindex). A green test asserting behaviour that doesn't exist is a fabricated result, which this framework's testing standard forbids outright. Filed as [issue #71](https://github.com/jjoyjoshua/new-aidlc-employee-exchange/issues/71); human confirmed AC-07 ships proven for the commitments that do hold, with this gap linked.                                                                                                                              | Write the test anyway and mark it "known failing" / skip it. Rejected: a red or skipped test is never acceptable proof (`ai/gates/delivery.md`, `ai/roles/qa.md` guardrails); route the gap to a bug issue instead. |
| D-05 | Do not claim AC-02's "bottom bar" for the <768px shell — file it as a second gap instead.                                                                      | The manual sweep found the mobile nav rendering at the TOP of the page (`position: static`, confirmed via `getComputedStyle`/`getBoundingClientRect`), while `inception/design/ia.md:68-76` explicitly and deliberately specifies a fixed BOTTOM bar with a stated rationale (thumb reach; top tabs rejected). `app-shell.css:9`'s own comment already named this as a known, deferred gap. Filed as [issue #70](https://github.com/jjoyjoshua/new-aidlc-employee-exchange/issues/70); human confirmed the same treatment as D-03 (linked gap, not a blocker).                                                                                 | Block the US-033 PR until a shell fix lands. Rejected: this story verifies, it does not build; the human chose to ship with the gap linked, same as the desk-keyboard finding.                                       |
| D-06 | Fixed an unrelated, pre-existing API boot crash (issue #69) as a prerequisite, in its own commit, before the verification sweep could run at all.                | `apps/api` crashed on every boot (`web-push`'s named ESM exports don't resolve under Node's real loader, only under Vitest's transform) — sign-in itself was unreachable, blocking 9 of 10 screens. Human explicitly chose this option over skipping the authenticated screens or working around it.                                                                                                     | Skip the authenticated screens and leave the sweep partial. Rejected: the human chose to unblock it instead, and the fix was small, well-isolated, and covered by its own regression test citing #69.               |
| D-04 | AC-06 is proven by spawning `node tools/aidlc-check.mjs` from a test, not by re-implementing contrast math.                                                    | `tools/aidlc-check.mjs:474-534` already computes WCAG AA contrast for every text-on-surface token pair in both themes and currently reports zero shortfalls. A second implementation is a second source of truth that can drift from the first.                                                                                                                                                                                                                                 | Re-derive contrast ratios directly from `tokens.css` in a new test. Rejected: duplicate logic, no added confidence over calling the existing, already-passing check.                                     |
