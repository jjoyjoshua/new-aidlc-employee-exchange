# US-017 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                                                   | Rationale                                                                                                                                                                                                                        | Alternatives rejected                                                                                                                          |
| ---- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | No status radio on the add-desk form; every new desk is created Active, per the story's ACs and edge cases     | SCR-007's approved frames show one, but no AC in US-017 names it, and a control with no AC cannot be proven under this project's delivery gate. Human decision, 2026-09-19 (see Architect design note §1.1)                     | Building the radio to match SCR-007. Rejected: it would add a second required request field, a new form component, and two icon assets on the strength of a screen spec the story itself contradicts. Tracked instead as [issue #49](https://github.com/jjoyjoshua/new-aidlc-employee-exchange/issues/49) |
| D-02 | SCR-007's `Surface` line (naming `/admin/desks/new` as a route) is treated as stale and not implemented         | Every approved hi-fi frame and the screen's own Layout section (corrected 2026-09-10) draw a same-screen dialog over SCR-006, not a page; the `Surface` line predates that correction (Architect design note §4.1)              | Filing a second change-request issue for this line now. Deferred: it is a documentation-only correction with no code consequence, unlike D-01's contract-shaping conflict |
| D-03 | The desk-number format regex and normaliser live in `libs/contracts/src/desks.ts`, not `apps/api/src/domain/`   | `ai/standards/api-standards.md:19-21` literally names "the desk-number format" as a `domain/` rule, but the codebase's own precedent (booking-window: `refusalFor`/`lastBookableDate`/`addDays` live in `libs/contracts`; only clock-dependent `officeToday` lives in `domain/`) splits pure, non-clock-dependent rules into contracts so both the browser and the server test against one copy (ADR-002:76-79 already licenses this for the desk-number field by name). The desk-number rule has no clock dependency, so it follows the same split. `api-standards.md`'s wording is imprecise relative to actual practice, in the same spirit as the several stale story-number references the Architect's design notes have already flagged elsewhere in this repo | Putting the rule in `domain/` to match the standards doc's literal text. Rejected: it would fork the rule into a second copy the browser cannot import (`domain/` is server-only), defeating the reason ADR-002 put `evaluatePasswordPolicy` and the booking-window pure functions in `libs/contracts` in the first place |
| D-04 | No edit to `ai/standards/api-standards.md` for the new `desk_number_taken` error code                            | The file has no per-code enumeration table to add a row to — it shows one example JSON body (`desk_already_booked`) and a table of HTTP status classes, both of which already cover a `409` value-taken case by requirement ID (V-08 among them). The Architect design note speculated a row might be needed; verified against the live file, it is not | Adding a new "error codes" table to the standards doc. Rejected: out of this story's scope, and the file's existing shape (one worked example, not an enumeration) is a separate decision for whoever owns that doc |

Cite these as `US-017/D-01` (etc.) outside this folder.
