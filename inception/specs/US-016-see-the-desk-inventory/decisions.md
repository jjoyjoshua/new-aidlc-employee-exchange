# US-016 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision           | Rationale                                        | Alternatives rejected                              |
| ---- | ------------------ | ------------------------------------------------ | -------------------------------------------------- |
| D-01 | Move `fetch-desks.ts`, `use-desks.ts` and `use-desks.spec.ts` from `apps/ui/src/screens/all-bookings/` to `apps/ui/src/lib/`, updating both `AllBookings.tsx`'s and the new `Desks.tsx`'s imports | Two real consumers of the identical fetch (this codebase's own bar for `lib/` extraction, `lib/cancel-booking.ts:4-6`), per `design-note.md` §5.3 (open item 3). Copying instead would give US-016 and US-014 two parsers for one response, and `bookedAhead` would land in only one of them from day one | Copy the two files into `screens/desks/` unchanged. Rejected: it is a second source for the same fact, and the design note's own honest-cost note (editing one path string in US-014's `manifest.json`) is cheaper than the drift risk |
| D-02 | Product's own visible-but-disabled control copy: header/empty-state **Add desk**, each row's **Edit**, and **Deactivate**/**Activate** carry the reason "Not available yet — coming in a later release." as both `title` and a visually-hidden span, per the pattern `AdminBookingRow.tsx:66` already uses for its own non-cancellable action | The design note (§6.2, open item 8) left the exact wording to UX/PO and gave no committed release name; this string commits to nothing beyond "later," which is honest and reviewable without inventing a date or version number | A per-story-name reason ("Available once US-017 ships") — rejected: naming an internal story id to an administrator is jargon a screen must not surface (`guided-interaction.md`'s prime rule, applied to end-user copy, not just chat) |
| D-03 | Booked-ahead copy: `0 → "—"` (em dash, `aria-hidden`, paired with visually-hidden "No upcoming bookings"); `1 → "1 upcoming"`; `n → "${n} upcoming"` | The frame gives the plural and the dash only (`design-note.md` §7.2, open item 5); the singular and the dash's accessible text were unresolved. Picked the plain, unsurprising forms rather than blocking the story on UX copy sign-off | Leaving the singular pluralised ("1 upcomings") — obviously wrong; omitting accessible text behind the dash — rejected outright, it is the wire-to-pixel half of AC-05 itself (`design-note.md` §7.2) |
| D-04 | `StatusChip`'s new CSS classes are `.status-chip--active` / `.status-chip--inactive`, keyed on `status` alone (not on `kind`), matching the Architect's exact recommendation (`design-note.md` §4.2) | Keeps the existing per-status class convention (`available`/`taken`/`selected`/`confirmed`/`completed`/`cancelled`) rather than inventing a `kind`-prefixed scheme; a future `kind: 'account'` chip with the same `status` values (SCR-008) is expected to land on the same classes, which is correct since it wants the same visual treatment | A `kind`-scoped class (`.status-chip--inventory-active`) — rejected as unnecessary specificity for a component whose classes are already keyed on the visual state, not the caller |
| D-05 | Name the new screen-private inventory row `apps/ui/src/screens/desks/DeskInventoryRow.tsx` (and `DeskInventorySkeletonRow.tsx`), not `DeskRow.tsx` as the design note's file-placement table names it | `apps/ui/src/components/desk-row/DeskRow.tsx` already exists — a different, shared, employee-facing component (US-006/US-007's booking-selection row). The two do not import-collide (different folders), but an identical component name for two unrelated things is a needless grep/reading hazard this codebase does not otherwise have | Following the design note's literal name — rejected once the existing file was found during impact analysis; the design note's own reasoning (screen-private, not shared) is unaffected by the rename |

| D-06 | `Desks.tsx` implements its own **Try again** retry by bumping a local `retryKey` state that changes `stableFetch`'s identity, which is `useDesks`'s own effect dependency — without adding a `retry()` method to the shared `use-desks.ts` hook | `use-desks.ts` is now shared by two screens (D-01): `AllBookings`'s desk `Select` needs no retry (a desk-list failure there disables the select instead — US-014's own non-fatal treatment), but `Desks`'s ST-04 needs a real retry. Adding a `retry()` the first consumer never uses would be scope the shared hook does not need; the identity-bump device mirrors the "stableFetch" pattern `AllBookings.tsx` already uses for its own dependency-array stability, applied here to force a re-run on demand instead | Adding `retry()` to `UseDesksResult` for every consumer — rejected as unnecessary surface on a hook one of its two callers would never call; a screen-local `useAllBookings`-style hook duplicating `useDesks` entirely — rejected as the two-parsers-for-one-response drift D-01 already argues against |

Cite these as `US-016/D-01` outside this folder.
