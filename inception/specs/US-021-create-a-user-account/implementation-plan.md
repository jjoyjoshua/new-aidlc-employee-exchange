## Rollback

Revert the PR. No migration exists to roll back — `user_profiles`'s schema and defaults are unchanged. The wire is additive (`createAccountRequestSchema` is a new export; `admin.router.ts` gains one route, no existing handler is edited) except for `use-users.ts`'s new `markAdded` method, which is also additive (existing callers of `useUsers` are unaffected). The one non-additive risk a revert does **not** clean up on its own: an `auth.users` row created by a request that then failed at the `user_profiles` insert step AND whose compensating delete also failed (ADR-011 §Decision item 5's residual risk). That risk is bounded — closed by the `logger.error` lines Step 4 adds, not by code — but is real for any request in that narrow window; it is a `supabase auth admin` / manual cleanup concern, not a code rollback. See design note §2.6 and §9 (open item 1) for whether a follow-up issue should track it.
