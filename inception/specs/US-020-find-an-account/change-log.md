| 2026-09-20 | Human review of the running app found three real bugs the test suite could not catch (jsdom performs no layout): (1) the table's rounded corners never rendered — `border-collapse: collapse` does not reliably clip a colour-filled `<thead>` to a `<table>`'s own `border-radius`, and per-cell radii on `<th>`/`<td>` proved just as unreliable; fixed by moving the border/radius/shadow to a `.people-table-wrapper` with `overflow: hidden`. (3) The search icon was vertically misaligned — `top: 38px` guessed at the field label's height instead of centring within `.field__control` (the actual bordered input box), and separately, the injected `?raw` SVG had no `width: 100%; height: 100%` rule of its own (`status-chip.css`'s `svg` rule is the precedent), so it fell back to its default replaced-element size. One test (`AccountRowMenu.spec.tsx`'s divider placement case) was updated to query the portalled menu instead of the render's own `container` | Real-browser review surfaces exactly what a jsdom-only test suite structurally cannot: rendered geometry, corner clipping, and CSS custom-property cascade.
