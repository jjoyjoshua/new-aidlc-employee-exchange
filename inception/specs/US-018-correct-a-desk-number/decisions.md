# US-018 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision | Rationale | Alternatives rejected |
| ---- | -------- | --------- | ---------------------- |
| D-01 | `PATCH /api/admin/desks/:id`, not `PUT` or a verb sub-resource | Architect design note §3.1: no update-in-place precedent exists anywhere in the repo to contradict; `PUT` would invite a future `isActive` field into a body SCR-007 explicitly forbids it from; a rename modifies the resource rather than performing a refusable transition, so it fits `api-standards.md`'s noun-first shape rather than the `/:id/<verb>` pattern US-019 will need | `PUT /api/admin/desks/:id` (rejected — see above); `POST /api/admin/desks/:id/number` (rejected — a noun fits, so the sub-resource carve-out in `api-standards.md:9` doesn't apply) |
| D-02 | `200` response is `adminDeskSchema.omit({ bookedAhead: true })`, not the full `AdminDesk` | The write cannot produce `bookedAhead` without a second query, and the operation provably cannot change it (bookings reference `desk_id`, not the number) — sending it would mean either an extra query for an unchanged invariant, or echoing back a value the server never read | Recomputing the count with a new repository method (rejected — a fourth interface method and a second query to restate a fact AC-06 guarantees is unchanged); echoing the browser's own value (rejected — presents an unread value as a server fact) |
| D-03 | `404 desk_not_found` is built even though desks are never deleted | A well-formed request naming a resource that genuinely does not exist (a bad id from a non-browser caller) is not a server defect, and the error code and `notFound()` helper already exist at zero marginal cost. The browser has no UI state for it — it folds into `failed` (ST-07), since no approved copy exists for "that desk is gone" | Throwing (→ `500`) — rejected; conflates a well-formed not-found with a real defect |
| D-04 | One additive `describedBy?: string` prop on the shared `TextField`, composed into its existing `aria-describedby` list rather than replacing it | SCR-007 requires the upcoming-bookings note to be associated with the field via `aria-describedby`, not merely rendered nearby. `TextField`'s current `{...rest}` spread would silently let a naive `aria-describedby` prop overwrite the composed helper/error ids — this prop closes that hazard for every future caller, not just this one | Folding the note into the `helper` slot (rejected — `helper` renders inside a `<p>`, and an `Alert` is a `<div>`; invalid nesting, and loses the Alert's icon/tone); a loose, unassociated `Alert` (rejected — an accessibility regression in the one place the story says not to have one); a new `id`/`describedBy` pair on `Alert` too (rejected — costs a second shared-component surface for no benefit) |
| D-05 | `DeskFormDialog` is extended with `mode: 'add' \| 'edit'` rather than split into a second component; `use-add-desk-dialog.ts` is generalised (and renamed `use-desk-form-dialog.ts`) rather than duplicated | The component is screen-private (`screens/desks/`), so a `mode` prop is not the Complex shared-component surface US-017 avoided on `ConfirmDialog`; the delta between add and edit is small and declarative (title, initial value, confirm label, one extra note); AC-08 requires the save-guard behaviour to *match* the add path exactly, which a shared hook guarantees and two hooks could drift on | Two separate dialog components (rejected — duplicates ~90% identical markup and the `Dialog` composition); a second, sibling hook (rejected — duplicates the `inFlight` guard that is the actual thing AC-08 depends on) |
| D-06 | No fresh server read of the upcoming-booking count before showing AC-04's warning; the count already on the loaded `AdminDesk` is used as-is | Nothing is gated on the count in this story — the rename proceeds regardless (AC-03) — so a count that is stale by one booking cannot produce a wrong outcome, only a warning off by one, a cost RISK-012 already accepts. This is the opposite of what US-019 will need (its deactivation block *is* gated on the count, so it must recount server-side) — recorded here so that asymmetry isn't lost by the time US-019 is planned | Fetching a fresh count on dialog open (rejected — adds a loading state SCR-007 does not number, for a number nothing depends on) |
| D-07 | Two `it()`s proving AC-06 and AC-07 against a real Postgres database are added to the existing gated `bookings.repository.concurrency.spec.ts` file, not a new file or a new env gate | Both are assertions a fake client cannot make (that no `23505` fires on a genuine self-update; that a live join actually reflects a rename) — a fake client can only be told what Postgres did. The gate (`RUN_BOOKINGS_CONCURRENCY_TEST=1`), the skip-not-fail convention, and a `createDesk` fixture already exist there | A new `desks.repository.concurrency.spec.ts` with its own env gate (rejected — introduces a second convention for the same purpose with no benefit) |
| D-08 | Two documentation-only edits to `ai/standards/api-standards.md`: correcting the stale claim that the desk-number format lives in `domain/` (US-017 moved it to `libs/contracts` and missed this file), and adding a one-line convention distinguishing `PATCH` (modifies an attribute) from `POST /:id/<verb>` (a refusable transition) | The first is simply false today and this story is the one that reuses the schema at a route edge, making it the natural place to fix. The second captures D-01's reasoning where the next author (US-019) will actually look, without the overhead of an ADR for a one-sentence convention | An ADR for the verb convention (considered — rejected as disproportionate to a one-sentence, non-controversial convention; escalate to the human if they'd rather have the stronger record) |
