# US-008 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                 | Rationale                                                                                                                                                    | Alternatives rejected                                                                                                             |
| ---- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | Adopt the Architect's `usualDeskId` shape: one new top-level field on `availabilityResponseSchema`, not a per-row flag | Mirrors `myBooking` (US-007); a per-caller fact does not belong inside `desks[]`, which is otherwise a per-date fact about the office (design note §1.2) | A per-row `isUsual: boolean` on `deskAvailabilitySchema` — ships `false` on every row but one, and breaks the row/office-fact separation `myBooking` already set |
| D-02 | Eligibility (AC-05) resolved entirely server-side; the response never carries an id for a taken/inactive/absent desk | Same pattern as `myBooking` — the browser does one `===`, never re-derives a business rule (ADR-002's line between contract and rule) | A raw, unfiltered id with the browser cross-checking against `desks[]` — puts AC-05 in two places, and a divergence would label a Taken desk, which AC-05's own rationale calls "a tease" |
| D-03 | Repository read orders `booking_date desc, created_at desc` — the second key is required, not defensive | Cancelled bookings count toward history, and BR-001.2's cancel-then-rebook can leave two rows sharing the most recent `booking_date`; only `created_at desc` picks the row that replaced the other | A single `booking_date desc` key — returns either row non-deterministically on a tie, sometimes labelling the desk the employee explicitly rejected (design note §5) |
| D-04 | Compose `DeskRow`'s accessible name (desk number, availability word, hint) instead of adding a visible child element | `aria-label` on the row's `<button>` replaces the name computed from contents — a visible "your usual desk" span would never be announced (design note §6.2, F-3). Fixes a pre-existing gap where "Available"/"Selected" was never in the accessible name either, since the same fix covers it | A visually-hidden `<span>` inside the button — still invisible to the accessible-name computation once `aria-label` is present; removing `aria-label` entirely and relying on content — changes the existing name computation for every row, a larger and riskier change than composing the attribute |
| D-05 | Implement AC-05 per the story's own Edge Cases text (label follows a rename) rather than AC-05's literal "renamed" clause | AC-05's literal reading is not implementable: `bookings` stores `desk_id` only, no desk-number snapshot, so the server cannot detect a rename ever happened. The Edge Cases reading needs no new column — the id is stable across a rename | Implementing AC-05 literally — requires a new column recording the desk number at booking time, a schema change and a contract change nobody requested; silently picking one reading without flagging the contradiction — rejected, filed as [issue #37](../../../../issues/37) instead and confirmed with the human 2026-09-18 |

| D-06 | Hint text is "your usual" (not "your usual desk" as this plan originally drafted), right-aligned with a clock icon | The implementation plan's copy was drafted from the story's ASCII wireframe (SCR-003 line 44) without checking the actual hi-fi frame. Checked against the real Figma file (node 38:173) at the human's direction before styling: the approved hi-fi frame reads "your usual" with a clock icon, right-aligned opposite the desk number/chip — not inline text with no icon. The icon reuses the existing `Icon / clock` component (`icon-clock.svg`, already used by `NavIcon.tsx`, same Figma node family), not a new asset | Building to the plan's guessed copy/layout without checking the hi-fi frame — would have shipped a visual that does not match the approved design and would need a follow-up fix |

Cite these as `US-008/D-01` outside this folder.
