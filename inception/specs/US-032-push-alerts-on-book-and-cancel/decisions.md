# US-032 — decisions

> Technical choices made while implementing this story. Choices that change the shape of the
> system already went to the Architect — see [`design-note.md`](design-note.md). What follows are
> the ordinary implementation-level calls the design note leaves to DEV, including the design
> note's own "open items for the human" (§11), adopted here with the Architect's recommended
> default and flagged for override at Gate D1.

| ID   | Decision | Rationale | Alternatives rejected |
| ---- | -------- | --------- | ---------------------- |
| D-01 | `TTL: 86400` (24 hours) on every `sendNotification` call | Design note open item 1. The library's default is four weeks (`web-push-lib.js:13`), which would let a cancellation alert arrive long after the desk's date. 24h covers same-day and next-day bookings, the product's whole booking window (`db-design.md` booking-window rules) | The 4-week library default — a defect shape, not a feature, per the design note; a value computed from the booking's date — cleverness nobody asked for, and the design note explicitly recommends a fixed value |
| D-02 | `timeout: 10000` (10s socket timeout) on every `sendNotification` call | Design note open item 2. Unbounded is what turns one unreachable push service into a slow `POST /api/bookings` or `/users/:id/deactivate`, and NFR-01 requires the push not to delay the write it rides on | No timeout (library default is `undefined`) — rejected by the design note directly |
| D-03 | AC-03's example string (*"Your desk for Tue 9 Sep was cancelled by your office admin."*) is treated as **illustrative**, not literal copy. Push composes `Desk booking cancelled` / `Your desk ${deskNumber} for ${dateLabel} was cancelled${actorClause}.` — matching AC-02's requirement to name both the desk and the date | Design note open item 3. The example omits the desk number, which would violate AC-02 if copied literally; reading it as the email sentence with the desk elided to isolate the actor clause (its evident purpose) is the only reading consistent with both ACs. Flagged here as provisional pending UX sign-off, mirroring US-031/D-05's precedent for an analogous call | Asserting the literal example string in tests — makes AC-02 and AC-03 contradict each other; blocking the story on UX for a one-line string with an evident answer |
| D-04 | `notificationclick` closes the notification, then focuses an existing client window or opens `/` — no action buttons, no other deep link | Design note open item 4. The conventional minimum for a notification the story explicitly does not require to deep-link; doing nothing on click reads as broken, and the story's edge cases forbid inventing action buttons | No handler at all — leaves a dead click, which is worse than the minimum; a deep link into the specific booking — invents a rule no AC asks for |
| D-05 | The push fan-out is awaited inline inside the request that triggers it (booking, cancellation, or the deactivation cascade), not queued or fired-and-forgotten | Design note open item 5, and `app-architecture.md` §6's standing rejection of a queue at this project's size. A cascade of N bookings × M browsers adds N×M outbound round trips to one admin action, bounded by D-02's 10s timeout per call and run concurrently (design note §3.1) | Fire-and-forget — loses the delivery row's testability and risks an unhandled rejection; a queue — an ADR and a different story, forbidden by design note §12 |
| D-06 | The blind-SSRF residual `pushEndpointSchema` already accepts (US-031 §4.4: scheme + non-public-host validation, no hostname allowlist) is reconfirmed as the control for this story; no change to the schema | Design note open item 7 — US-031 accepted the residual explicitly "at US-032"; this is that story, so the acceptance is restated rather than re-derived | A hostname allowlist — already rejected in the US-031 design note for breaking the day a browser moves a host |
| D-07 | `infra/webpush`'s send wrapper imports `sendNotification` and `WebPushError` as named imports from `web-push` (CJS, no `exports` map) under `apps/api`'s ESM + `verbatimModuleSyntax` config | A CJS package with a plain `module.exports` object resolves through Node's cjs-module-lexer into named ESM imports. Design note open item 6 requires this proven at **runtime**, not just typechecked — the implementation plan's step for `infra/webpush` runs the real import against the installed package and pastes that evidence in the PR before the step is marked done | A default import (`import webpush from 'web-push'`) — `@types/web-push` has no `export =`, so this does not typecheck under `verbatimModuleSyntax` |

Cite these as `US-032/D-01` outside this folder.
