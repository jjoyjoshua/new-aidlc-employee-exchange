# US-001 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                                                                                   | Rationale                                                                                                                                                                                                                                                                                                      | Alternatives rejected                                                                                                                                                                                                       |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | `react-router-dom` for `apps/ui`                                                                                                           | AC-01, AC-02 and AC-03 all assert on addresses, and `apps/ui` had no way to map a URL to a screen. Approved by Joy Joshua on 2026-09-17. The protected-route pattern AC-03 needs is a first-class feature rather than something we build                                                                          | **TanStack Router** — stronger param inference, but more setup ceremony for ten flat routes and a smaller community. **Hand-rolled** — no dependency, but AC-03's redirect guard is exactly where a hand-rolled router goes subtly wrong |
| D-02 | Email is matched case-insensitively: trimmed, then lower-cased, **in our own code** before the auth call and before any profile lookup       | Three artifacts already imply it — BR-001.10's case-normalised uniqueness, `db-design.md` §1.1's `email citext`, and the story's own edge case calling it "the safe reading". A case-insensitive match can never be ambiguous when uniqueness is already normalised. Normalising explicitly means the behaviour is ours and has a test | **Relying on GoTrue to normalise** — it may, it is not our code, and it is not under test here. **Case-sensitive matching** — the story forbids shipping it without a decision. Owner for the BRD confirmation: Joy Joshua, routed to `/ba` |
| D-03 | The failure floor is a **constant in code** (`SIGN_IN_MIN_FAILURE_MS = 500`), not an environment variable. Tests inject a small floor as an argument | It is a security parameter, not a deployment one. `task-surfaces.md` §Escalate sends every `.env` key-name change to the human, and a floor that an operator can set to `0` is a security control with an off switch                                                                                             | **An env var** — invites per-environment drift in a security control. **No floor at all** — the deactivated path does strictly more work than either rejection and would emerge above the band                                 |
| D-04 | A failed **response parse** in `apiClient` is treated exactly as a `5xx` — it lands on the screen's existing service-unavailable state and logs the endpoint and failing field path | Closes ADR-002 follow-up 3, which is due at the first story that fetches. ST-05's message ("we can't reach the booking service right now") is honest about a server answering wrongly, so no new state and no new copy is needed. It is not a crash and not a white screen                                          | **A dedicated "bad response" state** — a new state on all ten screens for a failure the user cannot act on differently. **Throwing to an error boundary** — a white screen for a recoverable condition. Confirm with UX         |
| D-05 | **No `TRUST_PROXY` config key is added.** `requireHttps` asserts the `Strict-Transport-Security` header and refuses `x-forwarded-proto: http` in production; the redirect is left to the platform | `task-surfaces.md` §Escalate routes any `.env` key-name change to the human, and hosting is not chosen yet (`app-architecture.md` §7 item 3), so the correct value cannot be known. The Architect's design note names this fallback explicitly. Proving half of AC-08 in CI beats deferring all of it            | **Adding the key now with a `false` default** — an escalation for a value nobody can yet choose correctly. **Trusting `x-forwarded-proto` unconditionally** — lets an unproxied client spoof it                                |
| D-06 | The browser's request carries a **10 s timeout**                                                                                           | No NFR names a client timeout, and AC-07 needs one to have a defined "times out" path. 10 s is long enough not to cut off a slow phone connection and short enough that ST-05 appears before the user concludes the app is broken                                                                                | **No timeout** — AC-07's timeout clause would be untestable. **A shorter 5 s** — plausible, but more likely to show a failure message to a working slow connection                                                            |
| D-07 | `error.code` is parsed as `z.string()` on the wire, with the enum exported separately for switching                                          | A stricter schema would make an unknown **new** code crash an **old** tab — the same version-skew failure ADR-002 exists to prevent, pointed the other way. Taken from the Architect's design note §3.5                                                                                                          | **`z.enum([...])` on the wire** — turns every future code addition into a breaking change for any tab loaded before the deploy                                                                                                |
| D-08 | `mustChangePassword` ships in the sign-in response **now**, although US-004 is what acts on it                                               | A changed response shape is Complex by `task-surfaces.md`. Adding one boolean in US-004 would re-tier a story that would otherwise be Medium, for no reason                                                                                                                                                     | **Adding it in US-004** — a Complex change to save one field today                                                                                                                                                           |
| D-09 | RLS deny-all is enabled **on every table in the same migration that creates it**, rather than on all five tables in migration `0001`         | ADR-001's follow-up says "all five tables as part of the first migration", but four of those tables do not exist yet, so the literal instruction cannot be followed. The intent — RLS on from the beginning rather than retrofitted — is fully served. Recording the re-reading rather than quietly diverging       | **Creating all five tables in `0001`** — a migration for tables no code reads is untested schema, and every migration is Complex                                                                                              |
| D-10 | Copy lives in the UI, keyed on `code`. The server sends the same ST-04 sentence as its `message` purely so the three failure bodies are byte-identical on the wire | ST-05 has no server message at all — a network failure produces no response — so the screen must own copy regardless. Owning half of it in two places is the drift. The server's `message` here is a wire-uniformity value, not user-facing copy                                                                   | **Rendering the server's `message` directly** — leaves ST-05 with no copy source and splits ownership. Recorded so the apparent duplication is not "fixed" later                                                              |

| D-11 | **No Tailwind.** The Figma connector returns React + Tailwind; it is converted to plain CSS driven by `tokens.css`, which `apps/ui/src/styles/index.css` already imports | The returned markup is a high-fidelity non-interactive prototype, not code to paste. The project has no CSS framework, and adding one to avoid a conversion would be a dependency decision taken sideways rather than on its merits. Because the Figma variables carry the same names as `tokens.css`, the conversion is mostly mechanical | **Installing Tailwind** — a new dependency (the human's call, not a persona's) adopted as a side effect of a tooling default. **CSS modules** — reasonable, but a second styling idiom for a project that has not chosen one; defer to the team |
| D-12 | The login backdrop ships from **`inception/design/assets/login-backdrop.svg`**, copied into `apps/ui/src/assets/`, not from the Figma asset URL | The Figma component's own description names the repo file as its source of truth, and `inception/design/README.md` makes the same point: a frame is a picture of the design, an SVG the product ships is part of it and must be versioned and diffed. Figma asset URLs also expire after 7 days | **Downloading the Figma asset** — a second source for the same artwork, with an expiring URL and no review trail |

| D-13 | **`react-router-dom` v7 (7.18.4), not v6** | `npm audit` reported two moderate advisories against react-router `6.0.0 – 7.17.0`: an open redirect via a backslash in `<Link>`/`useNavigate` (a CVE-2025-68470 bypass), and arbitrary constructor injection in SSR hydration. The SSR one does not apply — this is a Vite SPA. The open redirect does not apply *today* either, because every navigation in US-001 goes to a fixed path. But "return me to the page I wanted" is the most natural enhancement a sign-in screen ever gains, and that feature is exactly this advisory. The upgrade is free **right now** and only right now: no router code exists yet, so v7's breaking changes cost nothing. It peers on React >= 18, which this project has. `npm audit` is clean after it | **Staying on v6** — the version Joy Joshua's approval was taken against, and familiar, but it ships with two known advisories and the migration cost only grows once screens exist. Reversible: say so and I will pin v6 and record the advisories as accepted |

| D-14 | **`ws` is a declared dependency of `apps/api`, supplied to `createClient` as the realtime transport** | `createClient` builds a `RealtimeClient` in its constructor, unconditionally, and on Node below 22 there is no global `WebSocket` for it to find — so it **throws at construction**, before any call. The project targets `node >= 20` and runs 20.x, so without this the server cannot create a Supabase client at all and every sign-in returned `500`. Found by running the API; no test caught it. ADR-001's "No Supabase Realtime" is unchanged — nothing subscribes to a channel. This satisfies a constructor, it does not adopt Realtime. `ws` was already present transitively; declaring it turns an undeclared dependency into an honest one | **Raising `engines` to `>=22`** — cleanest long-term and removes this entirely, but it is a platform decision affecting everyone's local setup and CI, not a persona's. **Pinning `@supabase/supabase-js` nearer the `^2.45.4` the manifest asks for** — the range resolved to 2.109.0; pinning down trades this problem for missing upstream fixes. Remove this when the minimum Node becomes 22 |

Cite these as `US-001/D-01` outside this folder.
