# US-011 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision           | Rationale                                        | Alternatives rejected                              |
| ---- | ------------------ | ------------------------------------------------ | --------------------------------------------------- |
| D-01 | `cancel-booking.ts` moves from `apps/ui/src/components/existing-booking-state/` to `apps/ui/src/lib/cancel-booking.ts` | It now has two real consumers (`ExistingBookingState` on SCR-003, `MyBookings` on SCR-002) — the same "two real consumers in front of it" bar US-010 §0/§4.5 applied when it *refused* to extract `BookingRow`. Architect's design-note §5.2 recommended this over leaving it in place and importing across screens | Leaving it under `components/existing-booking-state/` and importing from `my-bookings/` — works, but makes a shared API seam look like one screen's private detail |
| D-02 | `ConfirmDialog`'s CSS is corrected to match its own Figma master component (480px card, `--c-scrim`/`--c-surface-overlay`/`--shadow-3` tokens, mobile bottom sheet) rather than left as the narrower, bordered, non-responsive version US-007 shipped | US-007 built the component ahead of any consumer requiring the mobile/error states this story needs, and never fully matched the approved `Dialog` master component (verified directly against Figma nodes `103:6156`–`104:2210`, all named `HF / SCR-002 · My bookings / ST-07…ST-10`). Fixing it here brings the *existing* SCR-003 consumer up to the approved design too, at no prop/API cost | Leaving the mismatch and building a second, SCR-002-only dialog — rejected per D-06 in US-007's own decisions (one shared primitive, not two copies) |
| D-03 | `ConfirmDialog`'s Escape-key handler is guarded by `!busy`, and the new header close (✕) icon is disabled under the same condition | SCR-002 ST-08 explicitly requires "Escape is suppressed while in flight"; the current handler has no such guard and would let Escape unmount the dialog (and, in `ExistingBookingState`, silently drop a cancel request's outcome) while a request is in flight — a live defect, not a new requirement (Architect design-note §5.1b) | Leaving the fix to a future bug report — rejected: this story's own AC-07 is the first acceptance criterion to assert the behaviour, so it is this story's to fix |
| D-04 | AC-10 (the cancellation email) is proven in this PR only at the unit level — asserting the service performs exactly one write on a successful cancel — with no actual email sent | US-029 is the story that builds the mailer; this story cannot prove delivery of something that does not exist yet. The one-write assertion is what makes AC-10's "no second email" true by construction rather than by testing (Architect design-note §1.5) | Stubbing a fake mailer just to assert a call was made — rejected as speculative generality: the seam does not exist yet, so there is nothing real to call |
| D-05 | AC-02's server-side refusal folds into the existing `404 booking_not_found` — it does not become a second new distinguishable outcome, even though the retryable message a person sees in the rare overnight-tab case (open item 1) will be less accurate than it could be | AC-02's own wording is "refused at the server," not "the caller is told a specific reason" (contrast AC-09's "they are told"); SCR-002 ST-09 draws exactly two outcomes and a third has no approved copy or frame (Architect design-note §2.2) | A second new code (`booking_not_cancellable`, 422) — rejected as the design note's "additive if the PO asks for it later" option, not a default |

**Amendment to `US-007/D-03`**, recorded per the design note's §3 instruction: `POST /api/bookings/:id/cancel`'s three originally-undiscriminated failure reasons ("no such booking", "not the caller's", "not currently confirmed") now resolve as two merged (unchanged, for the anti-enumeration reason D-03 gave) and one split off: a caller's own already-cancelled booking is now `409 booking_already_cancelled` (US-011/AC-09) rather than `404 booking_not_found`. D-03's security argument is unaffected — see `design-note.md` §1.2 and §3 for the full reasoning and the four docblocks corrected to match.

Cite these as `US-011/D-01` (etc.) outside this folder.
