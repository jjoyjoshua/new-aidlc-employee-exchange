# US-019 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                                                          | Rationale                                                                                                                                                                                            | Alternatives rejected                                                                                                                                    |
| ---- | -------------------------------------------------------------------------------------------------------------------| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | The AC-08 residual race window (a booking can land between the block-check and the write) is accepted and documented, not closed in this PR | No DB transaction exists in this codebase; the only atomic fix is a Postgres function, which is a migration in a protected path and a separate STOP-and-ask, not this story's scope. The damage is fully recoverable (nothing is cancelled) and self-revealing (an `Inactive` row with a non-zero count on the next load). Confirmed by the human 2026-09-19 | A Postgres function doing a conditional `UPDATE`; deactivate-then-revert-if-blocked (rejected — briefly leaves a desk wrongly inactive and the booking path has the identical gap anyway) |
| D-02 | `desks.updated_at` is not set by `setDeskActive`                                                                  | The column's own migration comment scopes it to REQ-016 ("last renamed"); this story is REQ-017. Setting it would silently widen the column's documented meaning. Confirmed by the human 2026-09-19 | Setting it on every state change, treating it as a general last-modified timestamp — rejected because it requires also correcting the migration comment and two READMEs to match, which is more churn than the story needs |
| D-03 | After a successful deactivation, the browser corrects its held `bookedAhead` to `0` locally (`markStateChanged`), rather than the server returning it | A successful deactivation only ever happens when the live count was zero — the browser is reading the meaning of a success it was given, not evaluating the business rule itself. Confirmed by the human 2026-09-19 | The deactivate route returning the full `AdminDesk` including `bookedAhead: 0` — rejected as an unnecessary asymmetry against the sibling `activate` response, which has nothing to report |
| D-04 | `countUpcomingConfirmedForDesk` is a new repository method (a `head: true` count), not a reuse of `listUpcomingConfirmedDeskIds` | The existing method returns every upcoming id in the office (~3,100 uuids at the 100-desk ceiling) to answer a question about one desk, on the hot path of a write. A dedicated count avoids transferring rows the caller would immediately discard | Filtering `listUpcomingConfirmedDeskIds(...)`'s result client-side — rejected for the unnecessary row transfer on every deactivation attempt |
| D-05 | `DeskDeactivateDialog` is one screen-private component composing `Dialog` directly; `ConfirmDialog` is not reused for ST-05 | `Dialog` refocuses the opener on unmount. Swapping `ConfirmDialog` (ST-05) for a different component (ST-06) would unmount/remount and bounce focus out to the row and back, and ST-06's footer (a navigation as primary action) is outside `ConfirmDialog`'s fixed vocabulary anyway | Reusing `ConfirmDialog` for ST-05 and building a second dialog for ST-06 — rejected for the focus-bounce and because `ConfirmDialogProps` cannot express a navigation as its primary action |
| D-06 | `toQueryString`/`parseFilters` are imported from `screens/all-bookings/filters.ts` into `screens/desks/`, left in place rather than moved to `lib/` | `filters.ts` is a pure, React-free module — nothing in `eslint.config.mjs`'s import boundaries (which govern `apps/api` modules) restricts it. Moving it is a zero-behaviour-change relocation that can happen later if a reviewer prefers | Duplicating a second `toQueryString` under `screens/desks/` — rejected as the exact drift US-014 built the shared module to prevent |
| D-07 | The activation-failure banner (copy + a page-level `Alert`) is implemented as drafted in `design-note.md` §8.4, but is not claimed as proof of any AC — AC-11 covers deactivation failure only | SCR-006 draws the behaviour, so building it avoids a visibly half-finished screen, but no acceptance criterion exists to test it against. Filing a `change-request` for `/ba` to add the AC is recommended, pending the human's decision to file it (not filed as part of this plan) | Leaving the control unbuilt until an AC exists (US-017's precedent for its own uncovered control) — considered, but the behaviour is small and already fully specified by the frames, so building it now and flagging the gap was judged the lower-risk path |

Cite these as `US-019/D-01` (through `D-07`) outside this folder.
