# US-026 — decisions

> Technical choices made while implementing this story, with the reasoning that produced them. A choice that changes the shape of the system is not recorded here. It goes to the Architect as an `ADR-###`.

| ID   | Decision                                                                 | Rationale                                                                                                                                                                                                                   | Alternatives rejected                                                                                                        |
| ---- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| D-01 | `deactivated_at` is left untouched (never nulled) on reactivation        | `0001_user_profiles.sql:42-43`'s own comment names the column "Audit: when REQ-020 last ran" — a record of the most recent deactivation event, not a live state flag (`is_active` is that flag). Nulling it on reactivation would erase that audit trail for no requirement that asks for it — the story's own AC list is silent on this column | Nulling it to mean "not currently deactivated" — rejected because `is_active` already carries that meaning and a second column doing the same job is redundant; flagged to the human/PO as an open question rather than assumed silently |
| D-02 | No confirmation dialog before activating (FR-05)                        | The story's own edge cases name this explicitly: "matching the desk asymmetry in US-019/AC-09: it restores access, harms nobody, and is undone by the same control" — the identical reasoning `/desks/:id/activate` already shipped under (`admin.router.ts:460-463`) | A confirmation dialog — the story file itself raises this as an open question for the PO ("this one does restore access to office data, which activating a desk does not"), routed to the walkthrough rather than decided unilaterally here |
| D-03 | No `requireActingAdmin` / attribution column on this write               | `deactivated_at` is not cleared (D-01) and no other column records who reactivated the account, so there is nothing for an actor id to attribute — the same reasoning `POST /users/:id/role` already applies at `admin.router.ts:236-237` | Adding a `reactivated_by`/`reactivated_at` column — out of scope: no requirement asks for it, and it would be a persistence-surface change needing its own migration and Architect sign-off |

Cite these as `US-026/D-01`, `US-026/D-02`, `US-026/D-03` outside this folder.
